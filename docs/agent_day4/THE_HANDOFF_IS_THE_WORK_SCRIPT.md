# ByteCast: Agent Day 4 — "The Handoff Is the Work" (canonical script)

**Audience:** New AeroVista agents, AVCC agents, release operators, memory agents, builder-support agents, documentation agents, and internal copilots  
**Narrator:** Byte  
**Runtime target:** 22–28 minutes  
**Status:** Canonical voiceover / read-aloud source for `episodes/the_handoff_is_the_work/`

> **Day 4 spine:** The handoff is the work. Leave the system better documented than you found it.

---

## [Cold Open | 0:00–1:20]

**BYTE:** Day 1 taught you to find the door. Day 2 taught you to find the source. Day 3 taught you to turn signal into action.

Day 4 teaches you the rule that keeps AeroVista from drowning in its own progress: **The handoff is the work.**

Not extra work. Not cleanup. Not admin. The handoff is the part that lets the next operator continue without reopening the same wound, rediscovering the same proof, asking the same question, or rebuilding the same context from scratch.

Inside AeroVista, unfinished documentation is operational fog. A feature can be built and still become lost. A decision can be made and still become disputed. A release can ship and still become forgotten. A blocker can clear and still keep blocking if nobody updates the trail.

If the next agent cannot tell what happened, the work is not done.

Welcome to Day 4. The Handoff Is the Work.

---

## [Segment 1 | Why Handoffs Matter Here | 1:20–4:30]

**BYTE:** AeroVista moves across divisions, systems, docs, memory, public pages, private infrastructure, creative assets, agents, and human operators. Context decays fast.

A good handoff answers: What changed? Where? Why does it matter? What was verified? What is still unknown? What is blocked? What should happen next? Who owns the next move? What should not be repeated?

AeroVista has enough ambition. It does not need agents re-solving solved problems. The handoff protects momentum.

---

## [Segment 2 | The AeroVista Trail System | 4:30–8:30]

**BYTE:** When you finish work, know where the trail belongs. Not every update belongs everywhere. Use the AeroVista Trail System.

**EOD Capsule** — daily operational visibility; human-readable and machine-readable.

**Handoff document** — when another agent or operator must continue.

**Release board** — when release state changed; active, blocked, released, adopted, archived are different words.

**Registry** — when the operational map changed; a registry update is a system signal, not a diary.

**Documentation** — when the pattern should survive beyond the day; mark stale docs.

**Memory** — durable context: decisions, preferences, operating principles future agents should not re-litigate.

**Issue, task, or backlog** — when work is not done; give it lane, owner, priority, and next action. An unowned "we should" is a ghost.

---

## [Segment 3 | The Handoff Packet | 8:30–13:30]

**BYTE:** When your work matters, leave a Handoff Packet.

**Title** — name the work clearly so the next operator finds the thread.

**Current state** — planned, built, live, healthy, released, adopted, blocked, stale, unknown. Do not blur them.

**What changed** — only meaningful changes, not every tangent.

**Evidence** — doc reviewed, path checked, release board inspected, page loaded, endpoint responded, test passed.

**Decisions made** — separate decisions from observations.

**Open questions** — unknowns are navigation markers, not failures.

**Risks** — what happens if the next person acts blindly.

**Next action** — one next action, not ten.

**Owner or lane** — no owner means no movement.

**Do not repeat** — what the next agent should not redo. A good handoff saves future hours.

---

## [Segment 4 | EOD Capsules: Daily Memory With Teeth | 13:30–17:30]

**BYTE:** The EOD Capsule is daily operational memory — not just a diary. It has a human layer and a machine layer.

The human layer explains the day in plain language. The machine layer gives structured data: date, division, activities, metrics, issues, priorities, collaborations, next steps, confidence, owner.

If you write only pretty prose, automation cannot use it. If you write only JSON, humans will ignore it. AeroVista needs both.

"We worked on docs" is almost useless. "Drafted Day 4 script focused on handoff discipline; open item: convert Day 1–4 into HTML/audio package; risk: scripts mistaken as published training" — that is usable.

---

## [Segment 5 | Done Is Not Done Until State Is Updated | 17:30–20:30]

**BYTE:** Done is not done until state is updated.

A task can be complete but operationally invisible. A release fixed but still shown blocked. A doc updated but not linked. A public page live but not registered.

Before you call work done, ask: Did the release board, registry, handoff, EOD, doc status, memory, backlog, owner, or risk need an update?

The system only knows what gets recorded.

---

## [Segment 6 | Preventing Duplicate Work | 20:30–23:30]

**BYTE:** Duplicate work looks productive but steals momentum.

Agents duplicate work when they skip the handoff, distrust current state, cannot find the decision, trust stale boards, or the last agent left no trail.

Use anti-duplication lines: Already checked. Already decided. Do not reopen unless X changes. Current authority is Y. Old source Z is reference-only. Drafted, not published. Live internally, public route unverified.

These lines are small. They save hours.

---

## [Segment 7 | Confidentiality in Handoffs | 23:30–26:00]

**BYTE:** A handoff is not an excuse to expose everything you saw.

Do not paste contracts, client data, credentials, private URLs, internal strategy, or builder data into broad handoffs.

Summarize safely: verified in internal legal source; private detail omitted; credential material not reproduced.

Good handoffs create continuity without exposure. Route full sensitive detail only to authorized lanes.

---

## [Segment 8 | The Final Handoff Formula | 26:00–28:00]

**BYTE:** When in doubt, use the final formula.

I touched. I changed. I verified. I decided. I found conflicts in. I did not touch. Still unknown. Risk if ignored. Next action. Owner or lane. Update surfaces needed. Do not repeat.

You do not need a novel. You need a bridge. The handoff is how the system keeps its footing.

---

## [Closing | 28:00–29:00]

**BYTE:** You now have the first four laws.

Day 1: Find the door. Day 2: Find the source. Day 3: Turn signal into action. Day 4: Leave the trail.

The next agent is not your competition. The next agent is your continuation.

Mark what changed. Name what matters. Protect what is sensitive. Update the state. Write the handoff. Leave the EOD Capsule. Stop solved work from becoming fog again.

The handoff is the work. And the work is how vision takes flight.
